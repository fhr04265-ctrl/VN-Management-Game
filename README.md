# 訪問看護ステーション経営シミュレーター MVP

訪問看護の新任管理者・管理者候補が、売上、利益、現預金、稼働率、チーム継続リスク、ケア品質、請求品質のつながりを体験するための研修用Webアプリです。

## 使い方

`index.html` をブラウザで開くと、スマホゲーム風に再設計した v2 版をそのままプレイできます。サーバー、データベース、ログイン、外部APIは使っていません。

GitHub Pagesを有効にすると、スマートフォンからもブラウザでプレイできます。

## v2の方針

- 最初から細かい経営指標を出しすぎず、現金・チームの余裕・ケアの安定・利用者数の4つを中心に見る
- プルダウン中心ではなく、今月の方針カードを選ぶスマホゲーム風UIにする
- 月末結果は数字だけでなく、スタッフや管理者の声として表示する
- 詳細な数字や推移グラフは「振り返り」にまとめる
- 「頑張って学ぶ」ではなく「遊んでいたら事業理解が深まる」体験を目指す

## 主な特徴

- 12か月研修モードと60か月経営モード
- 新規開設、既存引き継ぎ、高稼働疲弊ステーションのシナリオ
- 売上と現金入金の2か月ズレ
- 採用、利用者獲得、利用者終了、疲弊、品質、地域信頼の連動
- 現預金0円未満、看護師3名未満のゲームオーバー
- CSV出力

## 初期版の安全設計

- 外部通信なし
- データベースなし
- APIキーなし
- 環境変数なし
- 外部ライブラリなし
- 個人情報入力なし
- CSV出力時に数式インジェクション対策を実装
- 画面描画は `textContent` と DOM API を中心に実装

## 将来DBや外部公開を行う場合の注意

- Supabase等を使う場合はRLSを必ず有効化する
- テーブルごとに読み書きPolicyを設定する
- `service_role` や secret key をクライアントに置かない
- 管理者処理や複雑な認可はAPI/Edge Function経由にする
- 認証、認可、入力バリデーション、レートリミットを各APIで行う
- 研修結果に氏名やステーション名を紐づける場合は個人情報として扱う
- ログに個人情報や機密情報を出さない
- dependency scan / secret scan を導入する

## 現在の位置づけ

このMVPは、訪問看護ステーション経営の全体像を学ぶための試作品です。数値は現実の正確な再現ではなく、研修で因果関係を理解することを優先しています。
